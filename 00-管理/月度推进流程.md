# 月度推进流程

> 用法：每月 1 日由自动化任务执行，也可随时手动触发。全程遵循 `../05-方法/研究方法与模板.md` 的证据分级。总时间盒约 2.5 小时，超时未完成的事项顺延到下月，不压缩质量。

## 流程步骤

### 第 1 步 定位（5 分钟）

读 `../README.md` → `研究路线图.md`，确认当前阶段、优先模块与待办清单。

### 第 2 步 情报扫描（60 分钟）

按 `../04-情报/监测源清单.md` 逐项扫描月度源（官方协议与规范、平台动态、研究与数据），检索时注意信息时效。只登记影响研究判断的信息，逐条记下来源与日期。

### 第 3 步 去噪（扫描中同步执行）

- 只有 A/B 级证据可以进入模块文档"当前结论"区
- C 级信息只允许两个去处：登记为总纲新假设（H 表新增），或记入"下一步"
- 与 M1–M4 四模块无关的行业新闻一律不进库
- 同一事实多源报道时，取最早的一手源，不重复登记
- 已被新证据推翻的旧结论：改写并在研究日志留一行索引，不保留原文

### 第 4 步 研究推进（60 分钟）

处理当前优先模块"下一步"清单中可完成的事项。若当月有面板复测任务（M2），执行月度面板测试并把数据存入模块目录 data/ 子目录。

### 第 5 步 落盘更新

- 模块文档"当前结论"区：新增或改写条目，必须带 `[日期][等级]` 标记
- 总纲 `../01-总纲/研究框架.md` 假设表：更新验证状态
- `研究日志.md`：追加不超过 3 行
- `研究路线图.md`：更新任务状态
- 协议或平台政策出现重大变化时：在 `业务决策看板.md` 登记复审项
- 双语同步：中文文档改动的结论，同步修订 `../en/` 对应英文镜像（术语对照依据见英文镜像框架文档的 Terminology Notes）

### 第 6 步 重建 WIKI

在项目根目录运行：

```
powershell -NoProfile -ExecutionPolicy Bypass -File build_wiki.ps1
```

确认 `wiki/index.html` 的修改时间已更新（构建输出应显示中文 / 英文各 14 页）。

### 第 7 步 校验

四条硬校验：所有新结论带证据标记；研究日志已追加；英文镜像已同步；wiki/index.html 已重建。

## 禁止事项

- 不删除既有结论，除非有新证据推翻（推翻时注明依据）
- 不新建游离于六个目录之外的文档；新专题按 `../05-方法/研究方法与模板.md` 的专题模板放入对应模块目录
- 不手改 `wiki/index.html`——它是构建脚本的派生产物，一律改 Markdown 后重建
- 新增 Markdown 文档后，必须在 `build_wiki.ps1` 的 `$pages` 配置中登记（中英成对），才会进入 WIKI
