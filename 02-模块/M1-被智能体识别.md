# M1 被智能体识别（Recognition）

> 状态：协议冻结（`盲测协议.md` v1.0），首轮基线待执行 ｜ 最后更新：2026-09-01 ｜ 总纲：`../01-总纲/研究框架.md`

## 1. 定义

智能体及其背后的模型能准确理解一个业务实体"是谁、提供什么能力、什么价格、什么约束"。识别的产物是模型内部的实体表示：名称、类目、能力清单、差异化属性。识别错误或缺失意味着后续的发现、采用、复购全部失真——agent 无法推荐一个它不能正确描述的东西。

人类营销对标：品牌认知。区别在于，品牌认知追求"被记住并产生好感"，机器识别追求"被准确解析且无幻觉"。

## 2. 研究问题

- M1-RQ1：如何测量主流模型对一个指定实体的识别准确度？（方法本身是本模块第一个产出）
- M1-RQ2：哪些内容形态最易被机器正确解析——结构化数据（schema.org）、表格、llms.txt、API 文档、问答式说明，还是传统营销文案？
- M1-RQ3：llms.txt 的实际采用度与效果争议如何裁决？已有平台方表示并不依赖该文件，需收集各方原始表态
- M1-RQ4：同名实体、多语言名称、品牌更名场景下，实体消歧靠什么信号（知识图谱条目、权威源一致性、域名与社媒档案）？
- M1-RQ5：模型知识截止日期与实时检索（带搜索的 agent）对识别的影响差异有多大？分别对应哪些优化动作？

## 3. 方法与实验协议（草案）

模型心智盲测：固定一组标准化提问（"X 是什么 / 提供哪些服务 / 价格区间 / 与 Y 的区别"），在多个主流模型（ChatGPT、Claude、Gemini、Perplexity、带检索与不带检索两种模式）上执行，记录原文回答，按维度评分：类目正确性、能力清单准确性、价格准确性、幻觉条目数、差异点是否提到。每轮测试固定 prompt 与温度，间隔 4–8 周重复，形成趋势。

变量控制：先测基线（当前状态），再做单变量内容干预（例如只新增 llms.txt，或只补齐 schema），两周后复测对比。

## 4. 指标体系

| 指标 | 定义 | 采集方式 |
|---|---|---|
| 识别准确率 | 各评分维度正确项 / 应答项 | 盲测评分 |
| 幻觉率 | 编造的能力、价格、关系条目占比 | 盲测评分 |
| 关键属性覆盖 | 价格、约束、差异点被正确说出的比例 | 盲测评分 |
| 模型间一致性 | 同一实体在不同模型上描述的方差 | 跨模型对比 |
| 时效敏感度 | 检索模式与纯参数模式下准确率差值 | 双模式对照 |

## 5. 当前结论

- [2026-09][B] llms.txt 采用度：Top 10,000 网站约 5.6%–5.9% 部署有效文件（两份独立统计互证）；效果侧第三方分析未见其对 AI 引用的显著相关性——M1-RQ3 证据链（采用率低 + 效果存疑 + 平台不依赖）三缺一
- [2026-09][A] Google 官方澄清（2026-07）：llms.txt 不是 Google Search 的排名因子，不带来可见性或排名提升——平台方立场已齐 Google 一方，OpenAI/Anthropic 一手表态仍缺，RQ3 可进入部分裁决

## 6. 与商业化的连接

识别是所有对外承诺的地基。若 M1 证明"结构化内容显著改善识别"，则"实体识别体检与修复"本身就是可售服务（对应 `../03-商业化/业务机会矩阵.md` 机会 A1 的证据基础），也是自有业务上线的第一步动作。
